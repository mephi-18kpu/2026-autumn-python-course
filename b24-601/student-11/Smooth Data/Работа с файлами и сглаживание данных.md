# Работа с файлами в Python и сглаживание данных

Датчик может записывать измерения в файл, а программа — читать эти значения, обрабатывать их и строить графики. В этом занятии будем работать с текстовой таблицей, в которой каждая строка содержит время измерения и показание датчика.

## Файл, путь и файловый объект

Файл хранит данные между запусками программы. Путь указывает, где находится файл. После открытия Python возвращает файловый объект: через него программа читает или записывает данные.

Текстовый режим работает со строками `str` и использует кодировку для преобразования текста в байты и обратно. Бинарный режим работает с `bytes`; его выбирают, например, для изображений и двоичных пакетов измерений. Здесь используем текстовый режим и явно задаём `encoding="utf-8"`. Подробности описаны в [документации текстовых и бинарных потоков Python](https://docs.python.org/3/library/io.html).

Для путей удобно использовать `Path` из стандартного модуля `pathlib`:

```python
from pathlib import Path

lesson_directory = Path(__file__).resolve().parent
input_path = lesson_directory / "data" / "sensor_data.txt"
```

`__file__` содержит путь к выполняемому файлу Python. Вызов `resolve()` получает абсолютный путь, а `.parent` — каталог скрипта. Оператор `/` присоединяет к пути имена каталогов и файлов. Само создание `Path` не открывает файл и не создаёт его на диске.

Относительный путь `Path("data") / "sensor_data.txt"` отсчитывается от текущего рабочего каталога программы. Этот каталог может отличаться от каталога скрипта. Привязка к `__file__` позволяет находить данные рядом со скриптом независимо от места запуска. В интерактивной консоли `__file__` обычно отсутствует; примеры занятия предназначены для `.py`-файлов. См. [документацию `pathlib`](https://docs.python.org/3/library/pathlib.html).

## Два способа открыть и закрыть файл

Открыть файл можно встроенной функцией `open(input_path, ...)` или методом `input_path.open(...)`, если `input_path` — объект `Path`. Оба варианта возвращают файловый объект. У этого открытого объекта есть метод `close()`; повторно открывать его через `file.open()` нельзя. Метод `.open()` относится к объекту пути.

### Явное открытие и закрытие

```python
file = input_path.open("r", encoding="utf-8")
try:
    text = file.read()
finally:
    file.close()

print(text)
```

Первая строка открывает файл для чтения. `read()` считывает оставшийся текст целиком, а `close()` закрывает файл и освобождает связанные с ним ресурсы. Блок `finally` выполняется и при нормальном завершении чтения, и при исключении внутри `try`.

Можно записать подряд `file.read()` и `file.close()`, но тогда исключение при чтении не позволит дойти до закрытия. Поэтому при ручном управлении используем `try/finally`. Если ошибка возникла при самом открытии, файловый объект ещё не получен и закрывать его не требуется.

Эквивалентная первая строка со встроенной функцией:

```python
file = open(input_path, "r", encoding="utf-8")
```

### Контекстный менеджер `with`

```python
with input_path.open("r", encoding="utf-8") as file:
    text = file.read()

print(text)
```

`with` управляет временем работы с файлом. При выходе из блока файл автоматически закрывается, в том числе при исключении. Вызов `close()` внутри этого блока не нужен. После выхода из блока строка `text` остаётся доступной, но чтение из закрытого `file` уже невозможно.

Для обычной работы с файлами используем `with`: связь между открытием файла и участком кода, который с ним работает, видна по отступам. Явное закрытие полезно понимать, чтобы видеть, какую работу выполняет контекстный менеджер. См. [раздел об открытии и закрытии файлов](https://docs.python.org/3/tutorial/inputoutput.html#reading-and-writing-files).

## Режимы открытия

| Режим | Назначение | Если файл существует | Если файла нет |
| --- | --- | --- | --- |
| `"r"` | Чтение | Содержимое сохраняется | Возникает `FileNotFoundError` |
| `"w"` | Запись заново | Содержимое стирается при открытии | Создаётся новый файл |
| `"a"` | Добавление в конец | Старые данные сохраняются | Создаётся новый файл |
| `"x"` | Создание нового файла | Возникает `FileExistsError` | Создаётся новый файл |

Режим чтения `"r"` используется по умолчанию. Буква `b` добавляет бинарный режим: например, `"rb"`. При бинарном открытии параметр `encoding` не задают. Режим `"w"` выбираем осознанно: прежнее содержимое теряется уже при открытии, даже если последующая запись не состоялась. Описание режимов есть в [справке `open()`](https://docs.python.org/3/library/functions.html#open).

## Чтение текста целиком и по строкам

`read()` удобен для небольшого файла, содержимое которого нужно получить одной строкой. Для последовательной обработки можно перебирать файловый объект:

```python
with input_path.open("r", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        print(line_number, line.rstrip("\n"))
```

Такой цикл не загружает весь файл в список строк. Обычно прочитанная строка заканчивается символом переноса `\n`. `rstrip("\n")` убирает этот символ при выводе; сам файл не меняется.

Ещё два метода: `readline()` читает одну следующую строку, а `readlines()` — все оставшиеся строки в список. Чтение продвигает текущую позицию в файле. После достижения конца следующий `read()` вернёт пустую строку. Чтобы начать заново, можно повторно открыть файл.

### Разбор числовой таблицы вручную

В наших файлах строки, начинающиеся с `#`, содержат пояснения. Остальные строки содержат два числа, разделённые пробелами или табуляцией. Каждую строку нужно очистить, разделить на поля и преобразовать поля в числа:

```python
time_values = []
sensor_values = []

with input_path.open("r", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        stripped_line = line.strip()
        if not stripped_line or stripped_line.startswith("#"):
            continue

        fields = stripped_line.split()
        if len(fields) != 2:
            raise ValueError(f"В строке {line_number} должны быть два числа")

        time_value, sensor_value = map(float, fields)
        time_values.append(time_value)
        sensor_values.append(sensor_value)
```

`strip()` удаляет пробельные символы по краям. `split()` без аргументов разделяет строку по пробельным символам, включая несколько пробелов подряд и табуляцию. `float()` преобразует текст в вещественное число. В файлах используем десятичную точку: `0.125`.

Этот пример показывает этапы чтения. Для дальнейших вычислений полученные списки можно преобразовать в массивы через `np.array()`. В таблице не должно быть пропущенных или нечисловых значений: они требуют отдельного правила обработки.

## Запись текста

Перед записью нужно создать каталог, если его ещё нет:

```python
output_directory = lesson_directory / "results"
output_directory.mkdir(parents=True, exist_ok=True)
report_path = output_directory / "report.txt"

with report_path.open("w", encoding="utf-8") as file:
    file.write("Обработка измерений\n")
    file.write("Размеры окон: 5, 21, 51\n")
```

`write()` записывает строку, но не добавляет перенос автоматически. Поэтому в примере указан `\n`. `parents=True` разрешает создать недостающие родительские каталоги, а `exist_ok=True` — использовать уже существующий каталог. Повторное выполнение примера обновляет отчёт целиком.

Для журнала, в который нужно дописывать новые события, можно использовать `"a"`. Для результатов одного вычисления удобнее `"w"`, чтобы повторный запуск не смешивал результаты разных запусков.

## Ошибки при работе с файлами

При открытии можно получить `FileNotFoundError`, если путь не существует, или `PermissionError`, если доступ запрещён. Ошибка `UnicodeDecodeError` при чтении текста может означать неверно выбранную кодировку. Ошибка `ValueError` при преобразовании в число означает, что содержимое не соответствует ожидаемому формату.

Сначала проверьте путь, существование файла и его первые строки. Не заменяйте неудачное чтение пустым массивом или выдуманными измерениями: следующая обработка тогда будет работать с неверными исходными данными.

## Числовые файлы и NumPy

Для регулярной таблицы чисел можно использовать `np.loadtxt()`. Эта функция выполняет чтение и преобразование в числовой массив:

```python
import numpy as np

data = np.loadtxt(input_path, encoding="utf-8", ndmin=2)
time_values = data[:, 0]
sensor_values = data[:, 1]

print(data.shape)
print(time_values[:5])
print(sensor_values[:5])
```

`ndmin=2` сохраняет двумерное представление даже для таблицы с одной строкой. Выражение `data[:, 0]` выбирает все строки первого столбца, а `data[:, 1]` — второго. По умолчанию `np.loadtxt()` пропускает комментарии после `#` и разделяет числа по пробельным символам; заголовки генератора совместимы с этими правилами. Пустые строки также пропускаются. См. [справку `np.loadtxt()`](https://numpy.org/doc/stable/reference/generated/numpy.loadtxt.html).

Перед обработкой проверьте, что таблица непустая, содержит два столбца, время возрастает, а шаг измерений постоянен. В данных генератора эти условия заданы при построении. Равномерное время важно для интерпретации размера окна: одинаковое количество отсчётов должно соответствовать одинаковому временному интервалу.

Для сохранения чисел используйте `np.savetxt()`:

```python
output_directory = lesson_directory / "results"
output_directory.mkdir(exist_ok=True)
output_data = np.column_stack((time_values, sensor_values))

np.savetxt(
    output_directory / "measurements_copy.txt",
    output_data,
    fmt="%.6f",
    delimiter="\t",
    header="Время (с)\tПоказание датчика (усл. ед.)",
    encoding="utf-8",
)
```

`np.column_stack()` объединяет одномерные массивы в столбцы таблицы; их длины должны совпадать. `fmt="%.6f"` сохраняет шесть знаков после десятичной точки, а `delimiter="\t"` разделяет столбцы табуляцией. К заголовку автоматически добавляется `# `, поэтому его можно пропустить при следующем чтении. Вызов перезаписывает файл. См. [справку `np.savetxt()`](https://numpy.org/doc/stable/reference/generated/numpy.savetxt.html).

## Генератор измерений

Рядом с конспектом находится [generate_sensor_data.py](generate_sensor_data.py). Он создаёт сумму пяти синусоид, добавляет шум и записывает два файла:

- `data/sensor_data.txt` — время и показания с шумом; основной входной файл для обработки.
- `data/clean_signal.txt` — время и сигнал без шума; опорные данные для сравнения результатов.

Каталог `data` и файлы появятся после запуска генератора. Для генерации нужен NumPy, а для графиков — Matplotlib. В командной строке `cmd`, находясь в каталоге занятия и используя подготовленное окружение, выполните:

```console
python -m pip install numpy matplotlib
python generate_sensor_data.py
```

Параметры находятся в начале скрипта:

| Параметр | Значение |
| --- | --- |
| Частота измерений | 500 отсчётов в секунду |
| Длительность записи | 10 секунд |
| Количество измерений | 5000 |
| Частоты синусоид | 2, 7, 12, 20 и 35 Гц |
| Амплитуды в том же порядке | 1; 0,7; 0,5; 0,35; 0,2 |
| Среднее значение распределения шума | 0 |
| Стандартное отклонение шума | 0,6 |
| Начальное значение генератора случайных чисел | 42 |

Чистый сигнал вычисляется по формуле:

$$
s(t) = \sum_{j=1}^{5} A_j \sin(2\pi f_j t).
$$

Здесь $A_j$ — амплитуда составляющей, $f_j$ — её частота в герцах, а $t$ — время в секундах. Показание датчика равно $x(t) = s(t) + \varepsilon(t)$, где $\varepsilon(t)$ — добавленный шум. Единицы значений сигнала условные.

Измерения идут через 0,002 с: от 0 до 9,998 с. Правая граница 10 с не включается, чтобы получить ровно 5000 отсчётов с частотой 500 Гц. Один и тот же набор параметров и seed даёт повторяемые данные в одном и том же программном окружении. Seed задаёт начальное состояние генератора, а не величину шума. Для получения другого набора измените `RANDOM_SEED`. См. [документацию генератора случайных чисел NumPy](https://numpy.org/doc/stable/reference/random/generator.html).

Каждый запуск обновляет оба файла. Чистый сигнал нужен для проверки: в реальном эксперименте он обычно неизвестен.

## Зачем сглаживать измерения

Случайный шум создаёт быстрые колебания показаний вокруг полезного сигнала. Скользящее среднее заменяет каждую группу соседних измерений их средним арифметическим. Случайные отклонения разных знаков частично компенсируются, и кривая становится более гладкой.

Среднее распределения шума равно нулю, но среднее конечной группы шумовых отсчётов обычно не равно нулю в точности. Поэтому сглаживание уменьшает влияние шума, а не устраняет его полностью. Оно также меняет сам полезный сигнал, если тот заметно изменяется внутри окна.

## Как работает скользящее среднее

Размер окна $W$ — количество соседних отсчётов, которые усредняются за один шаг. Сначала берём первые $W$ значений, затем сдвигаем начало окна на один отсчёт и повторяем вычисление.

Для массива $x$ длины $N$:

$$
y_i = \frac{1}{W}\sum_{k=0}^{W-1}x_{i+k}, \qquad i = 0, 1, \ldots, N-W.
$$

Например, для значений `[2, 4, 9, 3, 2]` и окна 3:

| Окно | Среднее | Позиция центра в исходном массиве |
| --- | --- | --- |
| `[2, 4, 9]` | 5 | Индекс 1 |
| `[4, 9, 3]` | 5,333… | Индекс 2 |
| `[9, 3, 2]` | 4,666… | Индекс 3 |

Получаются три значения вместо пяти. Соседние окна перекрываются, но каждое начинается на один отсчёт позже предыдущего.

### Полные окна и привязка ко времени

На занятии используем только полные окна: не добавляем вымышленные значения за краями записи и не уменьшаем окно возле границ. Поэтому при $1 \leq W \leq N$ длина результата равна $N-W+1$.

Для нечётного $W$ у окна есть центральный отсчёт. Обозначим $h=(W-1)/2$. Значение $y_i$ относим ко времени исходного отсчёта с индексом $i+h$. Например, среднее первых 21 значений относится ко времени отсчёта с индексом 10. На каждом краю записи теряется по 10 позиций.

Для построения графика сглаженного сигнала нужно взять соответствующую центральную часть массива времени. Нельзя использовать весь исходный массив времени: длины не совпадут. Нельзя также просто взять первые $N-W+1$ временных значений: тогда результат будет ошибочно сдвинут относительно центра окна.

Центрированное усреднение использует значения и слева, и справа от выбранного момента. Это удобно для уже записанного файла. При обработке поступающих измерений в реальном времени будущие отсчёты ещё недоступны, поэтому потребуется ожидание либо другое правило привязки.

### Почему сравниваем окна 5, 21 и 51

При частоте измерений 500 Гц соседние отсчёты разделены 2 мс. Точный промежуток между первым и последним отсчётом окна равен $(W-1)/500$ секунды:

| Окно | Промежуток от первого до последнего отсчёта | Ожидаемое поведение |
| --- | --- | --- |
| 5 | 8 мс | Слабое сглаживание, сохранение большей части быстрых деталей |
| 21 | 40 мс | Заметное сглаживание и ослабление быстрых колебаний |
| 51 | 100 мс | Сильное сглаживание с существенной потерей быстрых деталей |

У составляющей 20 Гц период равен 50 мс. Окно из 21 отсчёта охватывает значительную часть этого периода, поэтому значения разных знаков частично компенсируются. У составляющей 2 Гц период равен 500 мс: она меняется внутри небольшого окна медленнее и сохраняется лучше.

Эти размеры выбраны для учебного сравнения слабого, среднего и сильного сглаживания. Универсального лучшего окна нет: выбор зависит от частоты измерений и того, какие изменения сигнала нужно сохранить. Более гладкая линия сама по себе не доказывает, что результат ближе к чистому сигналу.

## Практическая работа

Создайте рядом с конспектом свой файл `signal_analysis.py`. На занятии анализируем сигнал во времени.

1. Загрузите `data/sensor_data.txt`. Проверьте количество измерений, форму таблицы, начальное и конечное время.
2. Выделите время и показания в отдельные массивы. Определите шаг времени и количество измерений в секунду.
3. Реализуйте функцию скользящего среднего с параметром размера окна. Для первой реализации используйте цикл по началам окон, срез массива и `np.mean()`. Функция должна работать с любым непустым одномерным числовым массивом и нечётным целым размером окна от 1 до длины массива; неподходящие аргументы должны приводить к понятной ошибке.
4. Вычислите результаты для окон 5, 21 и 51. Для каждого результата получите свой массив времени по центрам окон.
5. На одной области графика покажите исходный сигнал и три сглаженные кривые. Выведите участок от 0 до 2 с; используйте отдельную временную маску для каждой кривой. Добавьте подписи осей, сетку и легенду с размерами окон. Исходную кривую сделайте менее яркой через параметр `alpha`.
6. Сохраните график в `results/smoothing.png`, а каждый сглаженный сигнал — отдельной таблицей из времени и значения в `results/smoothed_5.txt`, `results/smoothed_21.txt` и `results/smoothed_51.txt`.
