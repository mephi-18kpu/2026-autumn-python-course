# Исключения в Python

## Что такое исключение

**Исключение** — это объект, с помощью которого Python сообщает о событии, прерывающем обычный ход выполнения. У объекта есть тип, например `ValueError`, и обычно есть сообщение с подробностями. Исключение может возбудить сам Python при выполнении операции, вызванная функция или ваш код с помощью `raise`.

Когда функция завершается через `return`, вызвавший её код получает результат и продолжает работу. Когда из функции выходит исключение, результат вызова не получен. Python прекращает выполнение текущего участка кода и ищет **обработчик** — участок программы, который может отреагировать на исключение.

1. Сначала Python ищет подходящий обработчик в блоках `try`, внутри которых выполнялась операция. Поиск идёт от внутреннего блока к внешнему.
2. Если подходящего обработчика нет, текущий вызов функции завершается, и исключение передаётся туда, откуда эту функцию вызвали. Поиск продолжается по цепочке вызовов.
3. Если обработчик найден, Python выполняет его. При обычном завершении обработчика программа продолжает выполнение после всей конструкции обработки. Действие, вызвавшее исключение, автоматически не повторяется.
4. Если исключение доходит до верхнего уровня скрипта без обработки, Python выводит сообщение об ошибке с трассировкой, и скрипт завершается.

Посмотрим, какие строки выполнятся при ошибке преобразования.

```python
print("Читаем количество билетов")
quantity = int("два")
print(f"Билетов выбрано: {quantity}")
```

Первая строка выводит сообщение. Вторая возбуждает `ValueError` внутри `int()`, поэтому присваивание `quantity` не выполняется. До третьей строки программа не доходит. Результат первой команды уже виден на экране. Исключение не отменяет действий, которые успели выполниться. [Документация Python об исключениях](https://docs.python.org/3/tutorial/errors.html#exceptions)

## Как исключение проходит через вызовы функций

**Стек вызовов** хранит сведения о вызовах, которые ещё не завершились. В примере основной код вызывает `show_total()`, а она обращается к `calculate_total()`. Цена одного билета составляет 350 рублей. Количество поступает строкой, поэтому перед умножением его нужно преобразовать в целое число.

```python
def calculate_total(quantity_text: str, ticket_price: int) -> int:
    """Рассчитать стоимость билетов по количеству и цене."""
    quantity = int(quantity_text)
    return quantity * ticket_price


def show_total(quantity_text: str) -> None:
    """Вывести стоимость выбранных билетов."""
    total = calculate_total(quantity_text, ticket_price=350)
    print(f"К оплате: {total} руб.")


show_total("два")
print("Готово")
```

`int("два")` возбуждает `ValueError`. Функция `calculate_total()` прерывается, поэтому присваивание `total` в `show_total()` тоже не выполняется. В обеих функциях нет обработчиков. Исключение доходит до верхнего уровня, и Python выводит **трассировку стека** (traceback).

```text
Traceback (most recent call last):
  File "tickets.py", line 13, in <module>
    show_total("два")
  File "tickets.py", line 9, in show_total
    total = calculate_total(quantity_text, ticket_price=350)
  File "tickets.py", line 3, in calculate_total
    quantity = int(quantity_text)
ValueError: invalid literal for int() with base 10: 'два'
```

В трассировке выше опущены указатели на отдельные выражения. Начните с последней строки. Она сообщает тип исключения и причину сбоя. Ближайшая запись над ней указывает на `int(quantity_text)`. Записи выше показывают, как программа дошла до этой строки.

## Как обработать исключение

В `try` помещают операции, исключения от которых здесь готовы обработать. Если одна из них возбуждает исключение, оставшаяся часть `try` пропускается. Python проверяет обработчики `except` сверху вниз и выполняет первый подходящий. Запись `as error` связывает объект исключения с именем `error`, чтобы его можно было использовать внутри обработчика.

Программа ниже делит число 360 на целый делитель, который вводит пользователь. Здесь преобразование текста может вызвать `ValueError`, а деление на ноль — `ZeroDivisionError`.

```python
dividend = 360
divisor_text = input("Введите делитель: ")

try:
    divisor = int(divisor_text)
    quotient = dividend / divisor
except ValueError as error:
    print(f"Введите целое число ({error})")
except ZeroDivisionError:
    print("На ноль делить нельзя")
else:
    print(f"Частное: {quotient}")
finally:
    print("Попытка деления завершена")
```

Если `try` доходит до конца, выполняется `else` и выводится частное. При ошибке преобразования или делении на ноль выполняется соответствующий `except`. В обоих случаях перед выходом из конструкции выполняется `finally`.

Обработчики относятся к операциям внутри `try`. Если исключение возникнет в `else` или для исключения из `try` не найдётся обработчика, Python выполнит `finally`, а затем исключение продолжит распространяться.

Обработчик подходит и для подтипов указанного исключения. Например, `ZeroDivisionError` относится к `ArithmeticError`. Если для деления на ноль нужен отдельный текст, `except ZeroDivisionError` ставят перед `except ArithmeticError`. [Документация Python об обработчиках исключений](https://docs.python.org/3/tutorial/errors.html#handling-exceptions)

## Как возбудить исключение из своего кода

Программа может задать собственные требования к значению. Например, громкость должна быть целым числом от 0 до 100. `int("150")` успешно вернёт число, поэтому проверку диапазона выполняет функция `parse_volume()`. При выходе за границы она явно возбуждает `ValueError`.

```python
def parse_volume(text: str) -> int:
    """Преобразовать строку в допустимый уровень громкости.

    Args:
        text: Уровень громкости, введённый пользователем.

    Returns:
        Целый уровень громкости от 0 до 100.

    Raises:
        ValueError: Ввод нельзя преобразовать в целое число от 0 до 100.
    """
    try:
        volume = int(text)
    except ValueError as error:
        raise ValueError(f"Уровень громкости должен быть целым числом, получено {text!r}") from error

    if not 0 <= volume <= 100:
        raise ValueError("Уровень громкости должен быть от 0 до 100")

    return volume


volume_text = input("Введите громкость: ")
try:
    volume = parse_volume(volume_text)
except ValueError:
    print("Настройка громкости отклонена")
    raise
else:
    print(f"Новая громкость: {volume}")
```

При вводе `громко` преобразование возбуждает исходный `ValueError`. Запись `raise ... from error` создаёт исключение с сообщением о громкости и указывает исходное исключение как его причину. Когда такая ошибка доходит до верхнего уровня, в трассировке видны и сбой в `int()`, и сообщение из `parse_volume()`.

Внешний обработчик выводит сообщение об отклонённой настройке. Затем `raise` без аргументов повторно возбуждает то исключение, которое обрабатывается в данный момент. [Документация Python о `raise` и цепочках исключений](https://docs.python.org/3/tutorial/errors.html#raising-exceptions)

## Как выполнить завершающее действие

При работе с ресурсом может понадобиться действие, которое должно произойти при любом исходе. Например, открытый файл нужно закрыть и после успешного чтения, и при ошибке во время работы с ним. Блок `finally` выполняется при выходе из защищённого участка. Если к этому моменту есть необработанное исключение, после успешного выполнения `finally` оно продолжает распространяться.

Для примера создайте текстовый файл `message.txt` в UTF-8 в текущем рабочем каталоге. Запишите в него строку `Добро пожаловать!`. Затем повторите запуск с пустым файлом.

```python
from pathlib import Path

message_path = Path("message.txt")
file = message_path.open("r", encoding="utf-8")
try:
    message = file.read().strip()
    if not message:
        raise ValueError("Файл не содержит сообщения")
    print(message)
finally:
    file.close()
    print(f"Файл закрыт: {file.closed}")
```

С текстом программа печатает сообщение и `Файл закрыт: True`. При пустом файле проверка возбуждает `ValueError`, но перед выводом трассировки программа выполняет `finally` и закрывает файл. Открытие стоит перед `try`. Если `open()` сам завершится исключением, файлового объекта ещё не будет.

Файловый объект также можно использовать с `with`. В начале блока файл доступен через имя `file`. При выходе из блока, в том числе из-за исключения, файловый объект закрывается автоматически.

```python
from pathlib import Path

message_path = Path("message.txt")
with message_path.open("r", encoding="utf-8") as file:
    message = file.read().strip()
    if not message:
        raise ValueError("Файл не содержит сообщения")
    print(message)
```

Обработчик `except` для ошибки пустого файла можно расположить вокруг `with`. К моменту перехода в этот обработчик выход из `with` уже завершён и файл закрыт. [Документация Python о `finally`](https://docs.python.org/3/tutorial/errors.html#defining-clean-up-actions) · [Документация Python об освобождении ресурсов через `with`](https://docs.python.org/3/tutorial/errors.html#predefined-clean-up-actions)
